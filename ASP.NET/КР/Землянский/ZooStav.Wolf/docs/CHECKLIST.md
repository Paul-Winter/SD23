# Чек-лист соответствия заданию

Вариант: **северный волк**, страница животного на поддомене зоопарка, Razor Pages (C#),
аутентификация и авторизация, публичная часть для посетителей, дневник для работников,
хранение в БД, доступ к данным через API, фильтрация записей.

## 2. Логины и пароли для проверки

| Логин | Пароль | Роль | Что проверять |
|---|---|---|---|
| `keeper` | `Keeper#2026` | Кипер | кормёжки, комментарии, правка **своих** записей, доступ к журналу |
| `keeper2` | `Keeper2#2026` | Кипер | вторая смена: видно, кто и когда вносил записи |
| `vet` | `Vet#2026` | Ветеринар | вакцинации, лечение, диагнозы; API `GET /api/audit` (200) |

## 3. Пошаговый сценарий демонстрации (5–7 минут)

1. **Публичная часть.** Открыть `http://localhost:5150/` — карточка волка Умки:
   описание, история особи, галерея (клик — увеличение), видео, веб-камера, ссылка «На главную зоопарка» (zoostav.ru).
2. **Поддомен.** Запустить профиль «ZooStav.Wolf.Web (поддомен wolf.localhost)» — адрес `http://wolf.localhost:5150/`,
   при этом в шапке появится зелёная полоса «Вы находитесь на поддомене животного».
   Из консоли: `curl -H "Host: wolf.zoostav.ru" http://localhost:5150/diary` — та же страница дневника.
3. **Дневник посетителя.** `/diary` → фильтры: тип «Кормёжка», период за неделю, поиск «рыба».
4. **Донат.** `/donate`: выбрать «Лечение», сумма 500 ₽ → сообщение о приёме доната; проверить «free donation» (сумма 0).
5. **Вход работника.** `/staff/login` → `keeper` / `Keeper#2026`.
6. **Последняя кормёжка.** На сводке: время последней кормёжки, ФИО специалиста, рацион, масса, «N ч M мин назад»,
   счётчики за 24 ч/7 дней. Нажать «Зафиксировать кормёжку» — время и специалист обновятся автоматически.
7. **Комментарии.** `/staff/diary` → под записью ввести комментарий → «Добавить комментарий»;
   в сводке справа он появится с ФИО, должностью и временем.
8. **Кто и когда менял.** Создать запись («+ Новая запись» → тип «Вакцинация», препарат, служебная запись),
   затем изменить её (кнопка «Изменить») — в истории записи и в `/staff/audit` появятся две строки:
   `Created` и `Updated` с перечнем изменённых полей «было → стало».
9. **Разграничение прав.** Войти как `intern` → кнопок изменения нет, `POST /api/diary` вернёт 403.
   Войти как `admin` → доступно удаление записи (тоже фиксируется в журнале).
10. **API.** Открыть `/swagger`, получить токен `POST /api/auth/login`, выполнить
    `GET /api/staff/feeding-status?slug=wolf`, `GET /api/diary?type=Feeding`, `GET /api/audit`.

## 4. Проверка поддомена в реальной эксплуатации

1. DNS: `A`-запись `wolf.zoostav.ru` → IP сервера приложения.
2. Веб-сервер/IIS: привязка (binding) `wolf.zoostav.ru` к тому же приложению, что и `zoostav.ru`;
   приложение принимает любые хосты (`AllowedHosts: "*"`).
3. Слаг поддомена хранится в БД (`Animal.SubdomainSlug`), поэтому новое животное (например, `nord.zoostav.ru`)
   достаточно завести в таблице `Animals` — код менять не нужно.
4. Домены настраиваются в `appsettings.json`: `Zoo:PrimaryDomain`, `Zoo:MainSiteUrl`, `Zoo:PublicBaseUrl`.

## 5. Ограничения демонстрационной версии

* Платёжный шлюз донатов эмулируется (провайдер `demo`) — интеграция выполняется в `DonationService`/`OnPostAsync`.
* Веб-камера: подключение реального потока реализовано (см. README, п. 9 и docs/API.md, п. 10) — HLS-поток,
  RTSP → HLS средствами встроенного ffmpeg, прокси MJPEG, кадры JPEG. В демонстрационном режиме без камеры
  показываются тестовые кадры.
* База — SQLite для запуска «в одну кнопку»; переход на MS SQL Server описан в README (п. 6).
* Медиафайлы — сгенерированные изображения и видео; в продакшене заменяются реальными съёмками вольера.
