# ZooStav — страница северного волка (ASP.NET Core, Razor Pages, C#)

Учебный веб-проект: **страница животного зоопарка** (северный волк), размещённая на **поддомене**
основного сайта зоопарка, с публичной частью для посетителей и кабинетом для работников,
дневником особи, комментариями, донатами и полным журналом изменений («кто, когда и что изменил»).

* Главный сайт зоопарка: **https://zoostav.ru**
* Страница животного (поддомен): **https://wolf.zoostav.ru** → в коде маршрут `/wolf/wolf`
* Технологии: **C# / .NET 8**, ASP.NET Core **Razor Pages**, **REST API** (Minimal API), **JWT + cookie**, **EF Core + SQLite**, Swagger.

---

## 1. Как открыть и запустить в Visual Studio

1. Скопируйте папку `ZooStav.Wolf` на компьютер.
2. Откройте файл **`ZooStav.Wolf.sln`** в Visual Studio 2022 (версия 17.8+) — проект откроется
   как **веб-приложение ASP.NET Core (Razor Pages)**.
   Требуется установленный компонент *«ASP.NET и веб-разработка»* и **.NET 8 SDK**.
3. Нажмите **F5** (или Ctrl+F5). Профиль запуска по умолчанию откроет страницу волка.
4. База данных (SQLite-файл `zoostav.wolf.db`) создаётся автоматически при первом запуске и
   сразу наполняется демонстрационными данными: стая волков, дневник, комментарии, донаты, журнал изменений.
5. Для проверки поддомена выберите профиль запуска
   **«ZooStav.Wolf.Web (поддомен wolf.localhost)»** — откроется адрес `http://wolf.localhost:5150/`.

> Если браузер не открылся автоматически: `https://localhost:7150` — публичная страница,
> `https://localhost:7150/staff` — кабинет работника, `https://localhost:7150/swagger` — API.

### Быстрый запуск из консоли

```bash
cd ZooStav.Wolf
dotnet run --project src/ZooStav.Wolf.Web
```

## 3. Что умеет приложение

### Публичная часть (посетитель, без входа)
* Страница животного на поддомене `wolf.zoostav.ru` — история конкретной особи, характеристики, стая, статус охраны.
* **Фотогалерея** с лайтбоксом, **видеозаписи** из вольера, **наблюдение через веб-камеру** (страница `/webcam`).
* Публичный **дневник стаи** с фильтрами: дата с/по, тип записи, особь, текстовый поиск, сортировка, постраничный вывод.
* **Донат на корм/лечение**, включая **free donation** (сумма 0 — просто слова поддержки), регулярные взносы,
  сводка сборов и список последних дарителей.
* Кнопка перехода на **главную страницу зоопарка** `https://zoostav.ru` (в шапке и в подвале каждой страницы).

### Кабинет работника (`/staff`, только после входа)
* **Сводка по особи**: последняя кормёжка (когда, кто кормил, чем, сколько часов назад, признак «просрочено»),
  число кормлений за 24 часа и 7 дней, статистика записей, болезней, вакцинаций, комментариев, донатов.
* **Быстрая отметка кормёжки** прямо со сводки: время и специалист подставляются автоматически.
* **Дневник особи/популяции** (`/staff/diary`): кормёжка, вакцинация, спаривание, потомство, болезнь, лечение,
  осмотр, взвешивание, перемещение, комментарий.
  Фильтрация по **дате**, **типу**, **пользователю (кто внёс)**, **особи**, поиск по тексту, сортировка, страницы.
* **Комментарии специалистов**: под каждой записью, с указанием автора, должности и времени добавления.
* **Журнал изменений** (`/staff/audit`): кто, когда (UTC+3) и что менял — входы в систему, создание, правка
  (со списком изменённых полей «было → стало»), комментарии, удаления, донаты. Фильтры: период, специалист, действие, сущность.
* **История одной записи** — на странице правки видно все изменения именно этой записи.
* **Донаты** (`/staff/donations`): список, фильтры, отметка «обработано» (действие тоже попадает в журнал).

### API (REST, JSON; полное описание — `docs/API.md` и `/swagger`)
* Публично: `/api/animals`, `/api/animals/{slug}`, `/api/diary` (публичные записи с фильтрами), `/api/feeding-status`, `/api/donations/summary`.
* По токену JWT: создание/правка/удаление записей дневника, комментарии, полный дневник с фильтрами,
  `/api/staff/feeding-status`, `/api/staff/dashboard`, `/api/audit`, `/api/staff/users`, список донатов.

### Права ролей
| Роль | Дневник | Комментарии | Правка | Удаление | API-журнал | Пользователи |
|---|---|---|---|---|---|---|
| Admin | ✔ полный | ✔ | любых записей | ✔ | ✔ | ✔ |
| Veterinarian | ✔ полный | ✔ | своих записей | — | ✔ | — |
| Keeper | ✔ полный | ✔ | своих записей | — | — | — |

## 4. Маршрутизация поддомена (главная «фишка» варианта)

Логика вынесена в `Infrastructure/SubdomainRoutingMiddleware.cs`:

* `wolf.zoostav.ru/` → страница животного (внутренний путь `/wolf/wolf`);
* `wolf.zoostav.ru/diary`, `/webcam`, `/donate`, `/diary/{id}` → соответствующие разделы **без смены адреса в браузере**;
* `zoostav.ru` — основной домен; запросы к `/api/...`, `/css`, `/js`, `/images`, `/staff` с поддомена **не переписываются**,
  поэтому API и кабинет работника доступны и с поддомена;
* слаг поддомена берётся **из базы данных** (`Animal.SubdomainSlug`), поэтому новые животные
  (`taimyr.zoostav.ru`, `yana.zoostav.ru`, `nord.zoostav.ru`) работают без изменения кода.

Проверка локально:
* профиль запуска «поддомен wolf.localhost» → `http://wolf.localhost:5150/`;
* либо эмуляция «как в бою» заголовком Host:
  ```bash
  curl -H "Host: wolf.zoostav.ru" http://localhost:5150/
  ```
* настройки доменов — в `appsettings.json` (`Zoo:PrimaryDomain`, `Zoo:MainSiteUrl`, `Zoo:PublicBaseUrl`).

Настройка в продакшене: в DNS создаётся запись `wolf.zoostav.ru` → IP сервера, в IIS/Kestrel добавляется
привязка (binding) `wolf.zoostav.ru`, приложение принимает запросы любых хостов (`AllowedHosts = *`).

## 6. Хранение данных

* Демонстрационный режим — **SQLite** (файл `zoostav.wolf.db`, создаётся автоматически, `EnsureCreated`), чтобы
  проект запускался «одной кнопкой» без установки СУБД.
* Для **промышленной** работы в `appsettings.json` уже лежит пример строки для MS SQL Server
  (`ConnectionStrings:SqlServerExample`). Переключение — одна строка в `Program.cs`:
  `opt.UseSqlite(...)` → `opt.UseSqlServer(...)` (потребуется пакет `Microsoft.EntityFrameworkCore.SqlServer`
  и `dotnet ef migrations add Initial` при необходимости миграций).
* Аутентификация в веб-интерфейсе — cookie, в API — **JWT** (HMAC-SHA256, срок 8 часов, issuer `zoostav.ru`).
* Пароли хранятся только в виде хеша (PBKDF2 из `Microsoft.AspNetCore.Identity.PasswordHasher`).

## 7. Про удалённый репозиторий группы

По заданию разработка ведётся в единой папке удалённого репозитория группы. Проект к этому готов:
в корне лежит `.gitignore` для Visual Studio, а сама папка `ZooStav.Wolf` является самодостаточным решением.

Если нужно загрузить в репозиторий, выполните из папки `ZooStav.Wolf`:

```bash
git init
git add .
git commit -m "ZooStav: страница северного волка (Razor Pages + API, дневник, донаты, аудит)"
git branch -M main
git remote add origin <адрес-репозитория-группы>
git push -u origin main
```

(сейчас проект **не** привязан ни к какому удалённому репозиторию — как вы и просили).

## 9. Веб-камера: подключение реального потока

Камера вольера настраивается секцией **`Webcam`** в `appsettings.json` — перезапуск кода не нужен.
Режим выбирается автоматически по заполненным полям либо принудительно: `Webcam:Mode` =
`hls` | `mjpeg` | `snapshot` | `demo`. Если ничего не задано, включается демонстрационный режим.

| Источник | Что заполнить | Как работает |
|---|---|---|
| **HLS-поток камеры/медиасервера** | `Webcam:StreamUrl = https://camera.zoostav.ru/wolf/index.m3u8` | страница играет поток плеером **hls.js** (файл лежит локально: `wwwroot/lib/hls.min.js`, внешний CDN не требуется); в Safari/iOS используется нативный HLS |
| **RTSP → HLS (транскодирование приложением)** | `Webcam:CameraInput = rtsp://user:pass@192.168.1.64:554/Streaming/Channels/101` | фоновая служба `WebcamStreamService` запускает **ffmpeg**, который пишет HLS в каталог `hls/`; приложение раздаёт плейлист по адресу `/hls/wolf.m3u8`. Сначала пробуется копирование потока (`-c:v copy`), если формат камеры не поддерживается копированием — перекодирование в H.264 (`TranscodeFallback`). ffmpeg корректно завершается вместе с приложением |
| **MJPEG-камера** | `Webcam:MjpegUrl = http://192.168.1.64/video` (+ `HttpUser`/`HttpPassword`) | поток проксируется «как есть» через `/api/webcam/mjpeg` — без перекодирования, минимальная нагрузка на CPU |
| **Камера с одиночным кадром** | `Webcam:SnapshotUrl = http://192.168.1.64/snapshot.jpg`, `PollSeconds = 3` | страница обновляет кадр через `/api/webcam/snapshot` раз в `PollSeconds` секунд, сервер кэширует кадр, чтобы не «дёргать» камеру |

Дополнительно:

* **`GET /api/webcam/status`** — текущий режим, живой ли поток, адрес источника, ошибки связи и подсказки по настройке;
* **`GET /api/webcam/snapshot`** — JPEG-кадр (с камеры, если режим `snapshot`/`mjpeg`, иначе демо-кадр) — удобно для превью и мобильных приложений;
* **`GET /hls/wolf.m3u8`** (+ сегменты `*.ts`) — раздача HLS-плейлиста и сегментов, которые создаёт ffmpeg;
* при обрыве связи с камерой страница не «ломается»: MJPEG-поток переключается на кадры, HLS-плеер — на периодические снимки;
* проверка без правки конфигурации — переменными окружения: `Webcam__CameraInput=rtsp://…`, `Webcam__StreamUrl=…`, `Webcam__MjpegUrl=…`, `Webcam__SnapshotUrl=…`.

Требования к окружению для RTSP-режима: установленный **ffmpeg** (`Webcam:FfmpegPath` — можно указать полный путь)
и сетевой доступ к камере. Пример команды, которую приложение выполняет автоматически:

```bash
ffmpeg -rtsp_transport tcp -stimeout 5000000 -i "rtsp://user:pass@192.168.1.64:554/Streaming/Channels/101" \
  -an -c:v copy -f hls -hls_time 2 -hls_list_size 6 \
  -hls_flags delete_segments+independent_segments \
  -hls_segment_filename "hls/seg_%05d.ts" "hls/wolf.m3u8"
```

Каталог `hls/` — рабочий (в репозиторий не попадает, добавлен в `.gitignore`); неактуальные плейлисты
определяются автоматически (если файл не обновлялся больше минуты, приложение не считает поток живым).
