
Этап 1. Аналитика и проектирование 

• Формулировка темы и целей: обоснование актуальности единого окна для туриста (поиск билетов, жилья и справочной информации в одном месте).
• Анализ аналогов: обзор 3–4 существующих туристических агрегаторов (выявление плюсов, минусов и обоснование преимуществ вашего решения).
• Составление технического задания (ТЗ): фиксация функциональных требований (поиск авиабилетов, подбор жилья, база знаний/чек-листы для путешественников) и нефункциональных требований (адаптивность, скорость загрузки).
• Изучение документаций API: регистрация в партнёрских программах и получение тестовых ключей:
• Для авиабилетов — API партнёрской сети Travelpayouts (официальный инструмент интеграции Aviasales).
• Для жилья — API сервисов бронирования (например, Островок, Суточно.ру или Авито Недвижимость) либо разработка собственной базы объектов с переходом на внешние площадки.
• Проектирование архитектуры и БД: выбор базы данных (например, PostgreSQL или MongoDB) для хранения справочной информации, чек-листов и кэширования запросов, разработка структуры REST API.

Этап 2. Дизайн и вёрстка клиентской части 

• Прототипирование: создание вайрфреймов основных страниц (Главная с формой поиска, Страница результатов билетов и жилья, Раздел «Памятка туриста / Что нужно для перелёта»).
• UI-дизайн: подбор цветовой палитры, типографики и дизайн-системы в Figma.
• Разработка фронтенда (HTML/CSS/JS):
• Адаптивная кроссбраузерная вёрстка (под ПК и мобильные устройства).
• Реализация интерактивных форм поиска (выбор городов вылета/прилёта, дат, количества пассажиров) с валидацией полей.
• Создание интерактивного справочника путешественника (фильтры по странам, правилам провоза багажа, визовым требованиям и чек-листам сборов).

Этап 3. Разработка серверной части на Node.js 

• Инициализация бэкенда: настройка сервера на базе Node.js и фреймворка Express.js (или Fastify).
• Реализация прокси-запросов к внешним API:
• Настройка безопасного хранения API-ключей на сервере (через .env), чтобы не раскрывать их во фронтенде.
• Написание модулей для получения актуальных цен на авиабилеты и формирования корректных реферальных/партнёрских ссылок для перехода на покупку.
• Реализация модуля подбора жилья и формирования ссылок перехода на карточки объектов местного рынка недвижимости.
• Работа с собственной базой данных: создание API-эндпоинтов для выдачи справочной информации о правилах перелёта, документах и советах туристам (с возможностью фильтрации по направлениям).
• Оптимизация: добавление кэширования ответов от внешних API, чтобы снизить нагрузку и ускорить работу сайта.

Этап 4. Интеграция, тестирование и деплой 

• Связка фронтенда и бэкенда: подключение клиентского JavaScript (через fetch или axios) к собственному серверу на Node.js, обработка состояний загрузки (лоадеры) и ошибок (если сторонний API временно недоступен).
• Функциональное тестирование: проверка корректности формирования ссылок перехода на Aviasales и площадки недвижимости, тестирование фильтров справочника.
• Нагрузочное и UI-тестирование: проверка отображения на разных экранах и в разных браузерах.
• Развёртывание (Deploy): публикация проекта на облачном хостинге или VPS (например, Timeweb Cloud, Selectel или Render) для демонстрации работающего сайта на защите.

Этап 5. Написание пояснительной записки и подготовка к защите

• Оформление текстовой части диплома по ГОСТу:
• Введение: актуальность, цель, задачи, объект и предмет исследования.
• Глава 1 (Теоретическая): анализ предметной области, обзор существующих туристических сервисов, обоснование выбора стека технологий (HTML/CSS/JS, Node.js, REST API).
• Глава 2 (Проектная): проектирование архитектуры приложения, описание структуры базы данных, протоколов взаимодействия с API.
• Глава 3 (Практическая): описание реализации клиентской и серверной частей, тестирование и оценка экономической/практической эффективности.
• Заключение, список литературы и приложения (листинги кода, скриншоты интерфейса).
