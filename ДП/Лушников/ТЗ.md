# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
**на разработку веб-платформы «Marketplace-Project»**

## 1. Общие сведения
1.1. **Наименование системы:** Веб-платформа «Marketplace-Project».
1.2. **Назначение системы:** Обеспечение онлайн-торговли и мультимодальной логистики (наземной и воздушной с использованием беспилотных авиационных систем) в регионах с низкой плотностью населения и слаборазвитой транспортной инфраструктурой (тундра, Крайний Север, Чукотский АО, Республика Саха).
1.3. **Плановые сроки разработки:** 11.11.2026 — 31.01.2027 (согласно утвержденному календарному плану).

## 2. Требования к системе в целом
2.1. **Архитектура:** Чистая архитектура (Clean Architecture) или MVC. Разделение на Backend (Web API) и Frontend (SPA или MVC Views).
2.2. **Технологический стек:**
*   Язык и фреймворк: C# / ASP.NET Core Web API (или MVC).
*   База данных: MS SQL Server или PostgreSQL.
*   ORM: Entity Framework Core (EF Core).
*   Frontend: HTML, CSS, JavaScript или React/Vue.
*   Дополнительно: SignalR (для телеметрии и чата диспетчера), интеграция с API погодных сервисов, интеграция с «ЭРА-ГЛОНАСС» (для БАС).
2.3. **Требования к безопасности:** Настройка системы аутентификации и авторизации (ASP.NET Core Identity), защита от SQL-инъекций, XSS и CSRF. Разграничение прав доступа на основе ролей.

## 3. Роли пользователей и матрица доступа
В системе должно быть реализовано 6 ролей:
*   **Покупатель:** поиск товаров, корзина, оформление заказа, выбор способа доставки, отслеживание заказа, написание отзывов.
*   **Продавец:** создание магазина, добавление/редактирование товаров (с обязательным указанием веса и габаритов для расчета доставки), управление заказами, просмотр статистики.
*   **Администратор:** управление пользователями, модерация контента, управление категориями, настройка справочника населенных пунктов и маршрутов доставки.
*   **Оператор БАС (беспилотных авиационных систем):** планирование полетных заданий, предполетная подготовка, управление полетом, действия при нештатных ситуациях.
*   **Диспетчер логистики:** координация наземных и воздушных маршрутов, подтверждение вылетов с учетом погоды, управление очередью доставок.
*   **Водитель/курьер наземной доставки:** выполнение доставки в пункты, доступные наземным транспортом.

## 4. Требования к мультимодальной модели доставки
Система должна поддерживать и автоматически выбирать следующие типы доставки для конкретного населенного пункта:
*   **Наземная круглогодичная:** для населенных пунктов с дорогами с твердым покрытием.
*   **Наземная сезонная (зимники):** с учетом периода действия зимника и весогабаритных ограничений.
*   **Воздушная БАС (самолетного типа):** для дальних маршрутов и пунктов без дорог (требует площадки для взлета/посадки).
*   **Воздушная БАС (вертолетного/мультироторного типа):** для точной доставки без инфраструктуры (ограничения по весу и погоде).
*   **Комбинированная:** наземный участок до точки взлета, затем БАС до конечного пункта.

**Логика выбора (DeliveryRouterService):** Система автоматически определяет доступные способы доставки, анализируя текущий сезон, погодные условия (ветер, видимость, температура) и статус дорог (зимников). При неблагоприятных условиях вылет откладывается (статус «Ожидает погоды»), покупатель уведомляется.

## 5. Требования к базе данных (ER-диаграмма)
В БД должны быть реализованы следующие сущности:
*   **Базовые:** Users, Roles, Shops, Categories, Products, ProductImages, Orders, OrderItems, Reviews, Payments.
*   **Логистика:** DeliveryMethods, DeliveryZones, GroundRoutes, WinterRoads, DroneRoutes, DroneFlights, WeatherRestrictions, DeliveryOperators, DeliveryStatusHistory.

## 6. Требования к функционалу (MVP и продвинутый этап)

### 6.1. Минимально жизнеспособный продукт (MVP)
*   Регистрация/вход для всех 6 ролей.
*   Добавление товаров продавцом (с фото и параметрами веса/габаритов).
*   Каталог товаров с базовым поиском и фильтрацией.
*   Справочник населенных пунктов и доступных способов доставки.
*   Корзина и оформление заказа (без реальной оплаты, смена статусов).
*   Статусная модель заказа: «Ожидает погоды» → «Запланирован полет/рейс» → «В пути» → «Доставлен»/«Возврат».
*   Создание маршрутов администратором и уведомление покупателей (email/push).

### 6.2. Продвинутый функционал (Опционально)
*   Загрузка изображений (облако или локально).
*   Интеграция эквайринга (ЮKassa, Тинькофф, Stripe).
*   Система отзывов и рейтингов, чат (SignalR).
*   Интеграция с погодными API для автоматического пересчета ETA и блокировки вылетов.
*   Панель диспетчера с картой дронов в реальном времени.
*   Интеграция с «ЭРА-ГЛОНАСС» для подачи планов полетов.

## 7. Требования к интерфейсу (UI/UX)
Макеты должны быть созданы в Figma. Ключевые страницы:
*   Главная (витрина).
*   Каталог и карточка товара (с указанием доступных вариантов доставки для пункта покупателя).
*   Корзина и оформление заказа.
*   Личный кабинет покупателя (трекинг заказа).
*   Личный кабинет продавца (управление товарами).
*   Панель диспетчера логистики (карта маршрутов, статус зимников, погода).
*   Панель оператора БАС (полетные задания, журнал).

## 8. Требования к тестированию и развертыванию
*   **Тестирование:** Написание Unit-тестов (xUnit/NUnit) для ключевых сервисов (DeliveryRouterService, DroneLogisticsService, GroundLogisticsService).
*   **Развертывание:** Размещение на VPS или облачном сервисе (Azure, Yandex Cloud).
*   **CI/CD:** Настройка пайплайна через GitHub Actions для автоматической сборки и выгрузки проекта.
*   **Регуляторика:** Учет требований по подключению дронов к «ЭРА-ГЛОНАСС» (для аппаратов тяжелее 250 г) и согласование полетов в воздушном пространстве типа H.

## 9. Порядок контроля и приемки
Приемка осуществляется поэтапно согласно календарному плану (Периоды 1–3). Итоговая проверка включает демонстрацию работы MVP, прохождение Unit-тестов и проверку безопасности.
